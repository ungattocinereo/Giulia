Версия включает новый дизайн, круглые портреты с листьями, четыре карточки соцсетей, статический HTML для поисковиков, файлы обнаружения и исправления обработчика Telegram. Индивидуальная консультация — 5 000 ₽, семейная — 6 000 ₽, бесплатное знакомство — 20 минут; доступны онлайн-встречи и очный приём в Москве.

## Публикация и проверка

1. Проверить `npm run check` локально и в отдельной временной папке VPS, включая серверную сборку с временным `--outDir`.
2. Проверить полный подготовленный Caddyfile с окружением действующей службы. Меняется только блок PopovaTalk, остальные сайты сохраняются.
3. Атомарно опубликовать тег и рабочую ветку; дождаться обновления или запустить `/srv/Giulia/redeploy.sh`. Общая библиотека блокирует одновременные обновления и заменяет `dist` только после успешной сборки.
4. После публикации статики применить проверенный Caddyfile и выполнить `systemctl reload caddy`. Исходная конфигурация сохраняется для возврата.
5. Сверить коммиты GitHub/VPS, выполнить `npm run check:live`, проверить меню, FAQ, цены, изображения, маршруты формы и неизменность защищённых настроек.

Автоматические проверки не отправляют настоящих сообщений. Доступность Telegram-бота и права публикации проверяются методами чтения. Для проверки полной доставки нужна отдельная согласованная заявка через рабочую форму.

## Возврат при необходимости

Быстрый возврат выполняется на VPS под блокировкой `/srv/Giulia/.deploy.lock`: сохранить новую сборку отдельно, восстановить `dist` и рабочие скрипты из указанной защищённой копии. Если менялся Caddy, восстановить его исходный файл, проверить и выполнить reload. `.env`, webhook и общую библиотеку восстанавливать только при изменении соответствующих настроек.

Чтобы последующее автоматическое обновление также публиковало старую версию, создать новый коммит рабочей ветки с деревом файлов из `rollback-popovatalk-2026-10-01` и отправить его обычным push. Историю рабочей ветки не переписывать. Восстановление одной папки `dist` без возврата обработчика не откатывает отправку в Telegram.

Порядок регулярного обновления описан в [DEPLOYMENT.md](DEPLOYMENT.md).
