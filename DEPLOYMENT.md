## Подготовка

```bash
npm ci
npm run check
./deploy.sh --check
```

Просмотреть разницу подготовленной ветки с `origin/popovatalk_ru_alpha`. `deploy.sh --check` не изменяет сервер и не отправляет сообщение в Telegram.

В подготовленной версии оба серверных скрипта находят проект по собственному расположению. Это закрепляет перенос в `/srv/Giulia` в репозитории: раньше пути были исправлены только на сервере, а `git reset --hard` при следующем обновлении стирал бы исправления.

## Перед первым обновлением подготовленной версии

Сделать защищённую резервную копию **вне репозитория** на VPS. Она сохраняет текущие скрипты, секреты и опубликованную сборку:

```bash
ssh hostup 'bash -s' <<'REMOTE'
set -euo pipefail
umask 077
backup="/srv/backups/popovatalk/$(date +%Y%m%d-%H%M%S)"
mkdir -p "$backup"
cd /srv/Giulia
git rev-parse HEAD > "$backup/commit.txt"
git diff --binary > "$backup/server-changes.patch"
cp -p .env redeploy.sh "$backup/"
mkdir -p "$backup/scripts"
cp -p scripts/send-telegram.sh "$backup/scripts/"
cp -a dist "$backup/dist"
printf 'Backup: %s\n' "$backup"
REMOTE
```

Убедиться, что текущие незакоммиченные серверные изменения ограничиваются известными исправлениями путей. При иных изменениях сначала перенести их в репозиторий: общая библиотека выполняет `git reset --hard origin/popovatalk_ru_alpha`.

Сохранить серверный `.env` с исходными именами `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `RECAPTCHA_SECRET_KEY`. Локальный `.env` для разработки на VPS не копировать. Не заменять `/etc/webhook.conf` и конфигурацию Caddy файлами старого Docker deployment.

## Публикация изменений

После проверки подготовленного коммита перенести его в `popovatalk_ru_alpha`. Push в эту ветку может запустить настроенный GitHub webhook и обновить рабочий сайт, поэтому это уже публикация.

Если требуется ручной запуск уже опубликованного в рабочей ветке кода:

```bash
ssh hostup 'bash /srv/Giulia/redeploy.sh'
```

Скрипт берёт блокировку, получает рабочую ветку, устанавливает зависимости, собирает сайт в `dist.new.*`, проверяет `index.html`, заменяет `dist` и проверяет доступность сайта. При провале этой проверки библиотека восстанавливает предыдущую сборку. Рестарт Caddy или webhook для обычного обновления кода не требуется.

Библиотека удаляет старые сборки и оставляет до трёх `dist.prev.*`; журнал конкретного запуска находится в `.deploy-logs/`. Это общий серверный код вне репозитория. Его менять в рамках обновления сайта не требуется.

## Проверка после публикации

```bash
./deploy.sh --check
curl -I https://popovatalk.ru/
curl -I https://www.popovatalk.ru/
```

Открыть сайт, проверить фото/видео, переход к контактам, способы связи, политику конфиденциальности и мобильное меню. Успешная HTTP-проверка главной страницы сама по себе не проверяет доставку заявок.

Для полной проверки доставки отдельно отправить одну явно обозначенную тестовую заявку через рабочую форму с согласия владельца канала и проверить её появление в Telegram. Без такого теста подтверждены только доступность бота/канала и проверки обработчика с подменёнными сервисами.

## Откат

Если проблема возникла после успешной HTTP-проверки, автоматический откат уже не сработает. Можно восстановить `dist` из защищённой копии или конкретной `dist.prev.*`. Откат одной статики не восстанавливает обработчик Telegram: при проблеме с ним восстановить также соответствующий `scripts/send-telegram.sh` из той же резервной копии. Серверный `.env` заменять только если менялись его настройки.

Перед следующим обновлением исправить код в рабочей ветке, иначе webhook снова опубликует проблемную версию.
